**Verified directly:** `grep -n "MonteCarloNullOptions" lib/research/statistics.ts` shows the type used at two call sites (`runMonteCarloNull`'s parameter, `monteCarloFairnessDiagnostic`'s parameter) but its `export type MonteCarloNullOptions = { simulationCount?: number; seed?: number }` declaration — present in the version this codebase had two audit-cycles ago — is gone from the current file. I also confirmed `npm run build` (Vite/vinext, same transpile-don't-check model) **still succeeds** — this is a type-safety/CI hygiene defect, not a shipped-bundle defect. Severity: **P1** (breaks a documented, previously-green quality gate — this project's own convention, reaffirmed across every prior report in this repo, is to gate on `test + lint + tsc + build` together, not test+build alone). **Fix:** restore `export type MonteCarloNullOptions = { simulationCount?: number; seed?: number };` in `lib/research/statistics.ts` (trivial, one line, zero design judgment — flagging rather than silently fixing since this audit is intentionally read-only, matching v1's practice).
